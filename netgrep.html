netgrep

grep for the network, for a post-TLS world. modern replacement for ngrep with stream reassembly and encrypted traffic inspection.

the problem

ngrep is alive but architecturally frozen: single-packet matching, no TLS, no stream reassembly, no protocol awareness. In 2025, most traffic is encrypted. You can't grep what you can't see.

netgrep fills the gap between ngrep (too simple) and tshark (too heavy). It reassembles TCP streams before matching, decrypts TLS when you have the keys, and understands HTTP/1.1, HTTP/2, and DNS natively.

ngrep (1996)

  • Single-packet matching only
  • No TLS support
  • No stream reassembly
  • No protocol awareness
  • No structured output

netgrep (2025)

  • TCP stream reassembly (bidirectional)
  • TLS 1.2 + 1.3 decryption (AES-GCM, ChaCha20)
  • HTTP/1.1 and HTTP/2 parsing (auto-detected)
  • DNS query/response awareness
  • JSON output, hex dump, interactive TUI

usage

# grep DNS for a pattern
sudo netgrep -F "udp port 53" "lastpass"

# search a pcap file
netgrep -I capture.pcap "password"

# decrypt TLS and grep the plaintext
SSLKEYLOGFILE=keys.log sudo netgrep --keylog keys.log "session_token"

# HTTP-aware mode — match against headers and bodies
sudo netgrep --http "Authorization"

# interactive terminal UI
sudo netgrep --tui

stream reassembly

TCP streams are reassembled bidirectionally before matching. Data emits on PSH/FIN/RST. This is the killer feature — you match against complete application-layer payloads, not raw packets.

TLS decryption

TLS 1.2 and 1.3 decryption via SSLKEYLOGFILE. Supports AES-128-GCM, AES-256-GCM, ChaCha20-Poly1305. ECDHE-ECDSA, ECDHE-RSA, and RSA key exchange.

protocol modes

--http parses HTTP/1.1 and HTTP/2 (auto-detected via connection preface). --dns parses queries and responses. Match against headers, domains, record data.

interactive TUI

ratatui-based terminal UI with packet table, detail pane, and status bar. Live capture or pcap replay. For when you want to watch traffic flow in real time.
